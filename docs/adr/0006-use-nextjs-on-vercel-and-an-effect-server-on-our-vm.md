# Use Next.js on Vercel and an Effect server with Postgres on our VM

The Web App is a Next.js (App Router, TypeScript) application on Vercel. It holds no secrets and never touches the database: it reads the contract directly, connects wallets with `@hot-labs/near-connect` (which supports HOT Wallet inside Telegram), and calls the server's HTTP API for everything else. Win Cards are rendered with `next/og` from server data, so every shared Draw Proof link has a preview image.

The server is one long-running Effect application (Node) on our VM. It serves the HTTP API with `@effect/platform`'s HttpApi, whose definition lives in a shared package so the Web App gets a typed client from the same schema. It runs the Telegram bot with grammY long polling, so the bot needs no webhook or public URL. Bitrefill, NEAR, NEAR Intents 1Click, the Agent's model client (NEAR AI Cloud's OpenAI-compatible private inference through the `openai` SDK, with a plain tool-calling loop), and the purchase workflow are Effect services with typed errors, retries, and timeouts. A persistent process also runs the reconciliation loop that finishes or fails any purchase left pending by a crash, which a serverless host could not do reliably. All secrets (the operator's function-call key and the Bitrefill, NEAR AI, and Telegram keys) live only on the VM.

Postgres runs on the same VM, reachable only from the server, through Effect's own SQL layer (`effect/sql` with `@effect/sql-pg`, and `@effect/sql-pglite` locally) and its Migrator. Unique keys and row locks make purchase admission idempotent against retries and double clicks. The database holds Telegram links, Redemption Data, and the purchase and Draw records the server reads from its own confirmation transactions, so no chain indexer is needed. Locally, and for judges, the server falls back to PGlite (Postgres compiled to WebAssembly) when no database URL is set, so the README needs no Docker or database install. On the VM, Docker Compose runs the server, Postgres with nightly dumps, and Caddy for automatic HTTPS on the API's subdomain.

The repository is a pnpm workspace: `apps/web` (Next.js), `apps/server` (Effect), `packages/api` (shared HttpApi and schemas), and `contract/` (Rust, `near-sdk` 5, built with `cargo-near`). The UI uses shadcn/ui on Tailwind, themed with the pitch deck's palette and type (Space Grotesk and Inter), and adds only the components it uses.

The judges' demo runs on NEAR testnet with a test-USDC token that has a public faucet, because 1Click top-ups are mainnet-only; the recorded demo shows a real top-up and voucher on mainnet.

Amended 2026-11-07: Drizzle was replaced by `effect/sql`. Effect 4 ships SQL clients for Postgres and PGlite behind one `SqlClient` service, so the PGlite fallback is a layer swap, errors stay typed, and Drizzle and drizzle-kit are two fewer dependencies.

Rejected: running the server on Vercel (no persistent process for the reconciliation loop or bot polling), a managed Postgres (the VM is already paid for and the data is small), SQLite or libSQL (weaker concurrency primitives for the purchase workflow), LLM agent frameworks, and a chain indexer.
